# A股数据 Python 库调研报告（2025-2026）

> 调研日期：2026-05-19
> 目的：评估各库对个人股票模拟器项目的适用性

---

## 1. AKShare

| 项目 | 详情 |
|------|------|
| 版本 | 1.15.73（2025年初），持续迭代中 |
| GitHub | https://github.com/akfamily/akshare |
| Stars | 同类项目最高（10k+） |
| 许可证 | MIT |
| 维护者 | Albert King |
| 安装 | `pip install akshare --upgrade` |

### 维护状态

- **仍在活跃维护**，持续有新接口和 bug 修复发布
- 但 Issues 积压严重：截至 2026-05 仍有大量未关闭 Issue（#7268, #7266, #7264 等）
- 东财相关接口是问题高发区，新浪接口偶发故障
- 维护资源有限，接口响应速度慢

### 数据覆盖（A股相关）

| 数据类型 | 接口 | 数据源 | 稳定性 |
|---------|------|--------|--------|
| 实时行情 | `stock_zh_a_spot_em()` | 东方财富 | 中 |
| 历史K线 | `stock_zh_a_hist()` | 东方财富 | 高 |
| 分时数据 | `stock_zh_a_minute()` / `stock_intraday_em()` | 东方财富 | **低** |
| 五档盘口 | `stock_bid_ask_em()` | 东方财富 | **低** |
| 资金流向 | `stock_individual_fund_flow()` | 东方财富 | 中低 |
| 分钟K线 | `stock_zh_a_minute()` | 东方财富 | 中低 |
| 财务摘要 | `stock_financial_abstract_ths()` | 同花顺 | 中 |
| 三大报表 | `stock_financial_report_sina()` | 新浪 | 中 |
| 行业板块 | `stock_board_industry_name_em()` | 东方财富 | 中 |
| 个股资讯 | `stock_news_em()` | 东方财富 | **低**（已 broken） |

### 已知问题

1. **东财接口频繁失效** — 东财网页结构变更或反爬升级导致接口突然不可用
2. **返回空 DataFrame** — 接口不报错但数据为空
3. **新浪 IP 封禁** — `stock_zh_a_spot()` 重复调用会被暂封 IP
4. **分时数据时间范围有限** — 历史时间段较短
5. **接口无版本锁定** — 数据源变更导致接口行为变化，升级后可能 break
6. **stock_news_em 当前版本 broken** — 需改用直接 HTTP 请求东财搜索 API

### 适用性评估

- **优势**：覆盖面最广的免费库，无需注册，中文文档详细
- **劣势**：核心接口（分时/盘口/资金流向/资讯）稳定性差，不适合生产依赖
- **本项目现状**：已使用，用于分时/盘口/资金流向/分钟K线/财务/资讯，但已对部分接口改用直接 HTTP API 回退
- **建议**：保留用于日K/周K/月K等稳定接口，对高频/实时接口逐步替换为直接 API 调用

## 2. Tushare

| 项目 | 详情 |
|------|------|
| 版本 | Pro 版（tushare），旧基础版已停更 |
| GitHub | https://github.com/waditu/tushare |
| 许可证 | BSD（旧版），Pro 版有独立服务条款 |
| 维护者 | Jimmy Liu |
| 安装 | `pip install tushare` |

### 积分体系（Pro 版）

| 积分获取方式 | 积分值 |
|-------------|--------|
| 新用户注册 | 100 |
| 完善个人信息 | +20（合计 120 基础） |
| 学生认证 | +2000 |
| 推荐注册 | 50/人 |
| 提交 bug | 5-50 |
| 发表文章 | 100-1000 |
| 付费捐助 | 50 元 = 500 积分（10:1） |

### 数据权限门槛

| 积分 | 可访问数据 |
|------|-----------|
| 120（基础） | 日线行情、股票列表、IPO 新股、限售解禁 |
| 2000 | 个股资金流、财务数据、期货、期权、债券、外汇、指数、港股、行业、宏观 |
| 更高级 | 部分高级接口（Level2 等） |

### 关键变化与争议

1. **基础版已停更** — 旧版免费接口不再维护，所有新功能在 Pro 版
2. **积分年度清零** — 无论免费获取还是付费购买，积分一年有效
3. **实质收费化** — 高阶数据需付费积分，约 400 元/年维持 2000+ 积分
4. **学生友好** — 学生认证可免费获得 2000 积分

### 适用性评估

- **优势**：数据源稳定（自建数据库），接口行为一致，有数据工具
- **劣势**：免费额度极其有限，实质收费 400 元/年，实时行情/盘口/分时需高积分
- **本项目现状**：未使用
- **建议**：**不推荐**。个人模拟器项目不需要付费数据服务，且实时/盘口/分时数据仍需高积分

## 4. 其他库

### 4.1 efinance

| 项目 | 详情 |
|------|------|
| 版本 | 0.5.5+ |
| GitHub | https://github.com/Micro-sheep/efinance |
| 数据源 | 东方财富 |
| 安装 | `pip install efinance` |

- 基于东方财富 API，接口简洁，获取速度比 AKShare 快
- **同样面临东财接口不稳定问题**，与 AKShare 东财接口共享数据源
- 不推荐替代现有方案，稳定性问题相同

### 4.2 pytdx（通达信）

| 项目 | 详情 |
|------|------|
| 版本 | 1.72+ |
| GitHub | https://github.com/rainx/pytdx |
| 数据源 | 通达信服务器（TCP协议） |

- 通过通达信协议直连服务器获取数据，实时行情延迟低（秒级）
- 支持实时行情快照、1/5/15/30/60分钟K线
- **不支持**分时成交明细、五档盘口（仅一档）、资金流向、资讯
- TCP 协议方式与本项目 HTTP 架构不匹配
- 可作为实时行情的紧急备用数据源

### 4.3 xtquant（迅投QMT）

- 迅投 QMT 量化交易平台的 Python 接口
- **必须安装 QMT 客户端**，不适合轻量 Web 应用
- **不推荐**：与本项目纯 Web 架构冲突

### 4.4 gmdata（掘金量化）

- 需注册账号，部分数据需付费
- **不推荐**：平台依赖问题

## 5. 直接 API 方式

### 新浪财经 API

- 端点：`hq.sinajs.cn/list=sh600000` 等
- 数据：实时行情快照（价格、涨跌幅、成交量、买卖五档）
- 优点：延迟低、数据全（含五档）、无需注册
- 缺点：频率限制（重复调用会封 IP）、非官方 API
- 本项目用法：主要实时行情数据源，分页获取全市场行情

### 腾讯财经 API

- 端点：`qt.gtimg.cn/q=sh600000` 等
- 数据：实时行情快照（含量比、52周高低）
- 优点：量比/52周数据补充
- 本项目用法：补充量比+52周数据，仅对筛选后股票调用

### 东方财富 API

- 端点：多个（行情、资金流、板块等），需抓包获取
- 数据：最全面（行情+资金流+板块+资讯+财务）
- 优点：数据覆盖最广，JSON 格式规范
- 缺点：**反爬机制强**，接口频繁变更
- 稳定性：**低**，是 AKShare 不稳定的主要原因
- 本项目用法：个股资讯（直接 HTTP 请求东财搜索 API）

### 直接 API vs 封装库

| 维度 | 直接 API | 封装库 |
|------|---------|--------|
| 灵活性 | 高，可按需调用 | 受限于库的接口设计 |
| 稳定性 | 可快速自行修复 | 依赖库更新，响应慢 |
| 维护成本 | 需自行处理解析/异常/缓存 | 库已封装，但 break 时需等更新 |
| 实时性 | 直接调用，延迟最低 | 库可能有额外开销 |

## 7. 针对本项目的建议

### 当前架构评价

本项目 **新浪/腾讯直接 API + AKShare 补充** 的混合架构是正确策略。

### 优化方向

1. **逐步替换 AKShare 不稳定接口**：
   - 分时数据 -> 东方财富直接 HTTP API
   - 五档盘口 -> 新浪 API 已含五档数据，无需 AKShare
   - 资金流向 -> 东方财富直接 HTTP API
   - 个股资讯 -> 东财搜索 API（已实现）
   - 分钟K线 -> 东方财富直接 HTTP API

2. **保留 AKShare 用于稳定接口**：
   - 财务摘要（同花顺源，相对稳定）
   - 三大报表（新浪源）
   - K线历史数据（东财源，此接口较稳定）

3. **不建议引入新库**（Tushare 收费、BaoStock 无实时数据、efinance 同源不稳定、pytdx TCP 不匹配）

4. **最终目标架构**：
   - 新浪 HTTP API -> 实时行情（主）+ 五档盘口 + 大盘指数
   - 腾讯 HTTP API -> 量比/52周（补充）
   - 东财直接 HTTP API -> 分时/资金流向/分钟K线/资讯
   - AKShare（保留）-> 财务摘要/三大报表/日K历史

### 风险提示

- 所有非官方 API 存在随时变更的风险
- 应保持**多数据源回退机制**（已部分实现）
- 对关键数据做**本地缓存 + TTL**（已实现）
