## 二、North Star Metric

| 属性 | 定义 |
|------|------|
| **名称** | 模拟交易收益率（Total Return %） |
| **定义** | `(当前总资产 - 初始资金) / 初始资金 x 100%` |
| **数据源** | `daily_snapshots.total` 字段，首日 vs 最新日 |
| **可视化** | 大数字卡片 + 趋势箭头 + 资金曲线迷你图 |
| **目标** | 跑赢上证指数（年化 > 8%） |
| **告警阈值** | 单日回撤 > 5% 触发关注，> 10% 触发警告 |
| **为什么选这个** | 产品核心价值是"零风险练手"，收益率直接衡量练习效果 |

## 三、输入指标（Input Metrics，4个）

### 3.1 日均交易次数

| 属性 | 值 |
|------|-----|
| **定义** | `当日 buy + sell 交易笔数`，按日聚合后取7日均值 |
| **数据源** | `transactions` 表，按 `created_at` 日期分组计数 |
| **可视化** | 柱状图（近30天每日交易量）+ 当前值数字卡片 |
| **目标** | 每周 >= 3次交易（保持练习节奏） |
| **告警** | 连续7天无交易 = 用户流失信号 |

### 3.2 筛选使用率

| 属性 | 值 |
|------|-----|
| **定义** | `使用过筛选功能的会话数 / 总活跃会话数 x 100%` |
| **数据源** | `/api/market/spot` 请求中带筛选参数（price_max/volume_ratio等）的比例 |
| **可视化** | 环形图（各筛选项使用占比）+ 趋势线 |
| **目标** | > 60% 的行情请求带筛选条件 |
| **告警** | 筛选使用率 < 30% 说明用户可能不会用核心功能 |

### 3.3 AI分析调用次数

| 属性 | 值 |
|------|-----|
| **定义** | 每日 `/api/ai/analyze` + `/api/ai/score` 调用总数 |
| **数据源** | 后端访问日志或添加调用计数中间件 |
| **可视化** | 折线图（每日调用量）+ 累计数字 |
| **目标** | 活跃用户日均 >= 2次 |
| **告警** | 单IP超过限流阈值（analyze 10次/分, score 15次/分）|

### 3.4 自选股活跃度

| 属性 | 值 |
|------|-----|
| **定义** | `(自选股数量 > 0的用户数) / 活跃用户数 x 100%` |
| **数据源** | `watchlist` 表非空记录数 |
| **可视化** | 数字卡片 + 自选股操作热力图（添加/删除/移动频率） |
| **目标** | > 70% 活跃用户有自选股 |
| **告警** | 自选股7天无变化 = 用户可能不再跟踪 |

## 四、健康指标（Health Metrics，4个）

### 4.1 行情数据延迟

| 属性 | 值 |
|------|-----|
| **定义** | `get_spot_data()` 全量获取耗时（毫秒） |
| **数据源** | `market_data.py` 中计时装饰器或日志 |
| **可视化** | 折线图（P50/P95/P99 分位线），单位 ms |
| **目标** | P95 < 5秒（全量5500只） |
| **告警** | P95 > 10秒 黄色，> 20秒 红色 |

### 4.2 API 成功率

| 属性 | 值 |
|------|-----|
| **定义** | `HTTP 2xx 请求数 / 总请求数 x 100%`，按端点分解 |
| **数据源** | FastAPI middleware 或 uvicorn access log |
| **可视化** | 数字卡片（总体成功率）+ 表格（各端点明细） |
| **目标** | > 99% |
| **告警** | < 95% 立即调查，单端点连续失败 > 3次 |

### 4.3 缓存命中率

| 属性 | 值 |
|------|-----|
| **定义** | `缓存命中请求数 / 总请求数 x 100%`，按缓存类型分解 |
| **数据源** | `BoundedCache` 命中/未命中计数器 |
| **可视化** | 各缓存类型堆叠柱状图 |
| **目标** | 行情缓存 > 80%（60s TTL 下正常水平） |
| **告警** | 行情缓存命中率 < 50%（说明预热失效或TTL太短） |

### 4.4 自动交易系统状态

| 属性 | 值 |
|------|-----|
| **定义** | 自动交易开关状态 + 最近执行结果 + 错误日志数 |
| **数据源** | `auto_trader.py` 状态接口 + 日志 |
| **可视化** | 状态指示灯（绿=运行/黄=暂停/红=异常）+ 最近运行时间戳 |
| **目标** | 交易日正常运行，无未处理错误 |
| **告警** | 连续2个交易日未执行 或 单次执行报错 |

## 五、交易绩效指标（Trading Performance）

已有实现（`get_performance_stats()`），补充完整定义：

| 指标 | 定义 | 可视化 | 目标 | 告警 |
|------|------|--------|------|------|
| **总收益率** | (末日资产 - 首日资产) / 首日资产 x 100% | 大数字 + 资金曲线 | > 0%（不亏） | 回撤 > 20% |
| **年化收益率** | (末/首)^(365/天数) - 1 | 数字卡片 | > 8%（跑赢指数） | < -10% |
| **最大回撤** | 峰值到谷值的最大跌幅 % | 回撤面积图（水下图） | < 15% | > 25% |
| **胜率** | 盈利卖出次数 / 总卖出次数 x 100% | 仪表盘/进度条 | > 50% | < 35% |
| **盈亏比** | 平均盈利 / 平均亏损 | 数字卡片 | > 1.5 | < 1.0 |
| **平均持仓天数** | 卖出日期 - 买入日期的均值 | 数字卡片 | 3-30天（非日内非长持） | > 60天（变成长期投资） |
| **夏普比率** | (年化收益 - 无风险利率) / 收益标准差 | 数字卡片 | > 1.0 | < 0 |
| **资金曲线** | daily_snapshots.total 时序折线图 | 主图表区域 | 稳定上升 | 连续下跌 > 5天 |

## 七、审查周期

| 频率 | 审查内容 | 执行者 |
|------|----------|--------|
| **每日** | 交易盈亏、自动交易状态、API错误日志 | 自动（盘中监控） |
| **每周** | 收益率趋势、交易频率、胜率变化 | 用户自查 |
| **每月** | 完整绩效报告（vs 上证指数对比）、策略回顾 | 用户深度复盘 |
| **每季度** | 指标体系校准：目标值是否合理、是否需要新增指标 | 用户调整 |

## 八、告警规则

| 告警 | 条件 | 级别 | 响应方式 |
|------|------|------|----------|
| 大额回撤 | 单日亏损 > 5% | 高 | 前端红色闪烁 + 推送通知 |
| API故障 | 任一核心端点连续失败 > 3次 | 高 | 日志 ERROR + 前端降级提示 |
| 数据延迟 | 行情全量获取 > 15秒 | 中 | 日志 WARN + 前端显示"数据加载较慢" |
| 自动交易异常 | 执行报错或超时未运行 | 高 | 日志 ERROR + 状态灯变红 |
| 限流触发 | IP触及 analyze/score 限流 | 低 | 返回 429 + 提示"稍后再试" |
| 长期闲置 | 7天无任何交易 | 信息 | 可选：邮件/消息提醒"该复盘了" |

## 九、工具推荐

| 用途 | 推荐 | 理由 |
|------|------|------|
| **前端图表** | 已集成 `lightweight-charts`（TradingView） | K线/资金曲线统一技术栈 |
| **后端监控** | 添加轻量 middleware 记录请求耗时/状态码 | 不引入新依赖，FastAPI 原生支持 |
| **日志聚合** | Python `logging` + 文件轮转（已有） | 个人项目够用，无需 ELK |
| **告警推送** | 前端 toast 通知（即时）+ 可选 Server酱/ Bark（手机推送） | 国内可达，免费额度够用 |
| **数据分析** | SQLite 直接查询 + pandas 导出 | daily_snapshots 已有完整时序数据 |

## 十、实施优先级

### P0 — 立即可用（数据已存在）

1. **资金曲线图** — 数据在 `daily_snapshots`，只需前端渲染
2. **交易绩效卡片** — `GET /api/trade/performance` 已实现，直接展示
3. **账户概览行** — `GET /api/trade/dashboard` 已实现，优化布局

### P1 — 需少量开发（加计数器/middleware）

4. **API 成功率 + 延迟** — 加 FastAPI middleware 统计
5. **缓存命中率** — `BoundedCache` 加 hit/miss 计数器
6. **交易频率统计** — 从 `transactions` 表聚合

### P2 — 需要新基础设施

7. **AI 分析调用追踪** — 中间件或独立计数表
8. **自动交易健康检查** — 增强 `auto_trader.py` 状态上报
9. **外部告警通道** — Server酱/Bark 集成

### P3 — 锦上添花

10. **vs 上证指数对比** — 拉取指数数据叠加到资金曲线
11. **用户行为漏斗** — 筛选→详情→买入→加自选转化率
12. **A/B 测试框架** — 不同筛选默认值的转化效果
