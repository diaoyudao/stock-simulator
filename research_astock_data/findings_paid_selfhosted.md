# A股低成本付费与自建数据方案调研

> 调研时间：2026-05-19 | 适用：个人股票模拟器项目

---

## 一、低成本付费数据 API

### 1. Tushare Pro（积分制）

| 项目 | 内容 |
|------|------|
| 免费额度 | 注册100分 + 完善信息20分 = **120分** |
| 120分可用 | 日线行情(`daily`)、股票列表(`stock_basic`)、IPO、限售解禁 |
| 付费 | **50元 = 500积分** |
| 资金流向 | 需2000积分 ≈ **200元/年** |
| 财务报表 | 需2000+积分 |
| **关键限制** | 积分**一年有效期**，到期清零，需持续付费续积分 |
| 适合场景 | 需要规范结构化数据、不想处理爬虫/协议问题 |

**评价**：对StockSimulator而言，200元/年获资金流向+财务数据算合理，但积分过期机制意味着这是持续成本，不是一次性买断。

### 2. 聚宽 JoinQuant

| 项目 | 内容 |
|------|------|
| 免费额度 | 基础日线/分钟线可免费，研究环境每天有限运行时长 |
| 付费 | 专业版约 **299元/年**，开放因子库、Tick数据、更长回测 |
| 日调用限制 | 免费用户有频次限制，付费大幅放宽 |
| 数据覆盖 | A股行情、财务、行业分类、因子库 |

**评价**：299元/年性价比不错，数据质量有保障，但API主要服务于其回测平台，独立使用的数据导出能力有限。

### 3. 米筐 RiceQuant

| 项目 | 内容 |
|------|------|
| 免费额度 | 有限研究环境，基础行情在线查看，API批量导出受限 |
| 付费 | 个人版年费约 **数千元**，企业版需联系商务 |
| 数据覆盖 | A股/期货/期权，含Level-2 Tick、财务、龙虎榜 |

**评价**：偏机构级服务，对个人模拟器来说成本过高，不推荐。

### 4. 萝卜投研 Datayes

| 项目 | 内容 |
|------|------|
| 免费额度 | 基础财务数据浏览，API每月数百次请求 |
| 付费 | 个人专业版约 **399-699元/年** |
| 数据覆盖 | 财务数据、行业数据、券商研报、宏观指标为主 |

**评价**：偏基本面研究，非纯行情API，对模拟器帮助有限。

### 5. 付费方案对比总结

| 方案 | 年费 | 行情能力 | 财务数据 | 适合模拟器? |
|------|------|---------|---------|------------|
| Tushare Pro | ~200元(2000分) | 日/周/月K+分钟线 | 有(需积分) | 是，性价比最高 |
| 聚宽 | 299元 | 日线+分钟线 | 有 | 可选，但数据导出受限 |
| 米筐 | 数千元 | 全面(含L2) | 有 | 否，成本过高 |
| 萝卜投研 | 399-699元 | 弱 | 强 | 否，偏基本面 |

**结论**：个人模拟器场景下，Tushare Pro 200元/年是付费方案中性价比最优选择。

## 二、自建 / 开源数据服务

### 1. pytdx（通达信协议）— 自建首选

| 项目 | 内容 |
|------|------|
| 原理 | 逆向通达信协议，直连通达信行情服务器 |
| 费用 | **完全免费** |
| 数据范围 | 日/周/月K线、分时、逐笔成交、财务数据、板块 |
| 行情类型 | 标准行情 + 扩展行情两种协议 |
| 集成难度 | 纯Python，pip install pytdx |
| 实时性 | 支持，可做实时推送（需自行封装定时拉取） |
| Level-2 | 不支持 |
| 风险 | 非官方协议，存在被封/限流风险；合规性存疑 |

**自建架构**：
```
pytdx → 定时拉取行情 → Redis/SQLite缓存 → REST API对外服务
```

**评价**：零成本、数据覆盖全面，是当前项目的最佳自建方案。StockSimulator已有新浪+腾讯双源，pytdx可作为第三回退源或替代方案。

### 2. 通达信 TdxQuant — 官方方案

| 项目 | 内容 |
|------|------|
| 原理 | 通达信官方量化客户端，Python接口调用客户端数据 |
| 费用 | 免费版通达信客户端即可使用 |
| 数据范围 | 实时行情、历史K线、快照、财务、可转债 |
| 特色 | 通达信公式100%兼容，5000股批量跑公式 |
| 依赖 | 必须运行通达信客户端 |
| 实时推送 | 需自行封装 |

**评价**：适合已有通达信使用习惯的用户，公式复用能力强，但对纯Web服务场景来说依赖客户端运行是劣势。

### 3. vnpy — 全栈交易框架

| 项目 | 内容 |
|------|------|
| 定位 | 开源量化交易框架，非纯数据服务 |
| 数据能力 | 依赖网关（如pytdx网关）获取行情 |
| 内置模块 | DataRecorder数据记录，可对接MongoDB/MySQL |
| 优势 | 完整事件驱动引擎，天然适合实时处理 |
| 劣势 | 框架重，学习曲线陡；A股行情仍需pytdx做数据源 |

**评价**：如果只需要数据服务，vnpy过重。适合需要完整交易系统（策略+执行+风控）的场景。

### 4. xtquant / 迅投QMT — 券商级方案

| 项目 | 内容 |
|------|------|
| 原理 | 券商托管量化终端，Python API直连 |
| 费用 | 需开通券商账户，通常 **50万+资金门槛** |
| 数据范围 | Level-2实时行情、完整深度数据 |
| 合规性 | 完全合规，数据质量最高 |
| 局限 | 数据仅在QMT客户端可用，迁移受限 |

**评价**：专业量化方案，50万资金门槛对个人模拟器不现实，不推荐。

### 5. BaoStock — 稳定历史数据源

| 项目 | 内容 |
|------|------|
| 费用 | 完全免费 |
| 数据范围 | 日/周/月K线、分钟K线、复权数据、财务数据 |
| 特色 | 接口规范、数据稳定，支持前/后复权 |
| 局限 | 连接数有限制，需手动login/logout；无实时行情推送 |
| 适合 | 历史数据回补、回测 |

**评价**：BaoStock是补充历史K线和财务数据的优秀免费选择，可替代AKShare部分接口，稳定性更好。

### 自建方案对比

| 方案 | 成本 | 实时行情 | 历史数据 | 财务数据 | 集成难度 |
|------|------|---------|---------|---------|---------|
| pytdx | 0 | 有 | 有 | 有 | 低 |
| TdxQuant | 0 | 有(需客户端) | 有 | 有 | 中 |
| vnpy+pytdx | 0 | 有(需配置) | 有 | 有 | 高 |
| xtquant | 50万门槛 | L2 | 全面 | 全面 | 中 |
| BaoStock | 0 | 无 | 有 | 有 | 低 |

## 三、WebSocket / 实时推送选项

### 1. 新浪 / 腾讯 WebSocket

**结论：新浪和腾讯均未官方开放免费WebSocket行情API。**

- 新浪 `hq.sinajs.cn`：HTTP轮询接口，非官方，社区广泛使用
- 腾讯 `qt.gtimg.cn`：同上，HTTP轮询
- 两者均存在随时变更或限流的风险，无WebSocket推送

### 2. SSE vs WebSocket 技术选型

| 维度 | WebSocket | SSE |
|------|-----------|-----|
| 方向 | 双向 | 单向(服务器→客户端) |
| 协议 | ws/wss，需升级握手 | 标准HTTP |
| 复杂度 | 高(心跳/重连/状态) | 低(浏览器原生EventSource) |
| 适合 | 交易下单、双向互动 | **行情推送、数据大屏** |

**推荐**：行情推送场景用SSE更轻量、更稳。如果需要交易功能，则用WebSocket。

### 3. 自建实时推送架构

```
数据源（新浪HTTP / 腾讯HTTP / pytdx）
    ↓ 定时轮询 (3-5秒间隔)
行情服务 (FastAPI / Go服务)
    ↓ SSE (推荐) 或 WebSocket
前端 (React/Vue)
```

### 4. 第三方商业推送

| 服务商 | 费用 | 说明 |
|--------|------|------|
| 腾讯云金融数据 | 付费 | 商业级，稳定可靠 |
| 万得Wind | 年费数万 | 机构标配 |
| 同花顺iFinD | 年费数千-数万 | 机构级 |
| 东方财富Choice | 年费数千 | 中端选择 |

对个人模拟器来说，这些商业方案成本过高。

## 四、架构模式与最佳实践

### 1. 多源回退架构

```
Client → DataFacade → [主源: 新浪] ──成功──→ 返回
                     └──失败──→ [备源: 腾讯] ──成功──→ 返回
                                └──失败──→ [备源: pytdx] ──成功──→ 返回
                                           └──失败──→ [本地缓存] ──成功──→ 返回(标记旧数据)
                                                      └──失败──→ 返回错误
```

核心要素：
- **健康检查**：记录每个源的响应时间和成功率，动态调整优先级
- **熔断降级**：连续失败超阈值(如3次)则自动熔断，一段时间后半开探测
- **数据对齐**：不同源字段名/格式不同，适配层统一映射
- **交叉校验**：多源同标的数据比对，价格偏离超阈值告警

### 2. 多级缓存策略

| 层级 | 技术 | 用途 | TTL |
|------|------|------|-----|
| L1 | 进程内缓存(LRU) | 热点数据毫秒响应 | 3-60秒(行情) |
| L2 | Redis | 跨进程共享去重 | 分钟级 |
| L3 | SQLite/Parquet/DuckDB | 历史数据持久化 | 日级 |

**关键策略**：
- 实时行情：短TTL(3-5秒)，仅L1/L2
- 日K线：收盘后固化，全链路缓存
- 历史数据：首次加载写L3，后续本地直读
- 缓存穿透：不存在的代码缓存空值，短TTL
- 缓存预热：开盘前9:15批量预加载自选股

### 3. 轻量级数据管道（适合个人项目）

```
数据采集层              数据处理层           数据存储层         数据服务层
┌──────────┐          ┌──────────┐        ┌──────────┐      ┌──────────┐
│ 新浪/腾讯  │──┐      │  Python   │       │  SQLite   │     │ FastAPI   │
│ pytdx    │──┼──→    │  asyncio  │──→    │  /DuckDB  │──→   │ + SSE     │
│ BaoStock │──┘       │  + Polars │       │  /Parquet │      │ /WebSocket│
└──────────┘          └──────────┘        └──────────┘      └──────────┘
```

- **调度**：Python asyncio定时任务（无需Airflow等重型调度器）
- **存储**：SQLite(当前方案)或DuckDB(更优的分析查询性能)
- **服务**：FastAPI + SSE推送(比WebSocket更轻量)
- **数据处理**：Polars替代Pandas，多线程性能更好

### 4. 开源量化工具数据架构参考

| 项目 | 数据架构 |
|------|---------|
| AKShare | 直接HTTP爬取各网站，无缓存层，接口变动频繁 |
| Tushare | 统一REST API + 服务端缓存，积分控制访问 |
| BaoStock | 直连证券数据服务器，login/logout会话模式 |
| vnpy | Gateway模式，事件驱动，DataRecorder写MongoDB |
| qlib(Microsoft) | 本地数据+QLib Server，支持增量更新 |

### 5. StockSimulator当前架构 vs 优化建议

**当前**：
```
新浪(主) → HTTP分页轮询 → 内存缓存(60s TTL) → FastAPI → Vite前端
腾讯(补充量比/52周) → HTTP轮询
AKShare(分时/盘口/资金流/分钟K/财务) → HTTP
东方财富搜索(资讯) → HTTP
```

**优化建议**：
1. **加入pytdx作为第三回退源**：当新浪+腾讯都失败时，pytdx直连通达信服务器取数
2. **BaoStock替代AKShare部分接口**：BaoStock更稳定，适合历史K线和财务数据
3. **实时推送改SSE**：当前前端轮询API，改SSE推送可减少请求量
4. **加入L2缓存(Redis)**：多进程/多实例场景下共享缓存
5. **考虑Tushare Pro付费**：200元/年获得稳定的资金流向+财务数据API，替代不稳定的AKShare接口

## 五、综合推荐方案

### 对StockSimulator项目的推荐

#### 方案A：零成本优化（推荐先做）

| 优化项 | 具体措施 | 预期效果 |
|--------|---------|---------|
| 加入pytdx回退 | 作为第三数据源，新浪→腾讯→pytdx→缓存 | 数据可用性提升至99%+ |
| BaoStock替代AKShare | 历史K线、财务数据改用BaoStock | 接口稳定性大幅提升 |
| SSE推送 | 行情数据改SSE推送前端 | 减少无效轮询，降低延迟 |
| 缓存预热+熔断 | 开盘前预热，失败自动熔断切换 | 用户体验更流畅 |

#### 方案B：低成本升级（200元/年）

在方案A基础上：
- 购买Tushare Pro 2000积分(200元/年)
- 用Tushare API替代AKShare的资金流向、财务报表接口
- 获得更稳定、结构化的数据

#### 方案C：专业级（50万+资金门槛）

- 开通券商QMT账户
- 获得Level-2实时行情
- 合规数据源

**对个人模拟器来说，方案A已足够，方案B是性价比最优的付费升级。**

## 六、合规性提醒

1. 新浪/腾讯/通达信(pytdx)的免费接口均为**非官方渠道**，商业化使用存在法律风险
2. 个人学习/模拟器场景风险较低，但仍需控制请求频率，避免被封IP
3. 正式商业产品建议接入正规数据服务商(Wind/Choice/iFinD)
4. pytdx使用通达信协议属于逆向工程，合规性存疑
